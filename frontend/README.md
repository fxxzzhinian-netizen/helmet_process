# 头盔识别与复核前端

前端使用 React、TypeScript 和 Vite。项目总览、识别工作台和违章记录共用同源 `/api`。首页配图为生成的园区骑行场景，业务页面读取后台保存的现场照片、检测框和事件。

## 构建与运行

在 `frontend/` 执行以下命令。已用 Node.js 24 验证。

```sh
npm ci
npm run build
```

后台默认托管 `frontend/dist/`。独立开发可先启动后台，再运行 `npm run dev`。默认代理至 `http://127.0.0.1:8000`，其他地址可通过 `HELMET_API_ORIGIN` 指定。页面、图标和首页配图均随构建提供，浏览器无需访问外部 CDN。

## 演示路径

1. 首页保留原有园区首图与居中指标色带，首图按钮区域为滚动播报。下方展示违章趋势、居中的圆角环形地点图和小时分布，支持日期筛选；地点信息在悬停或点按时以无边框单行文字反馈。趋势、时段和业务指标可查回对应记录。
2. 识别工作台（`#/work`）保留顶部流体进度栏，上传按钮与进度条对齐。下方状态色带切换待处理、处理中、待人工复核、已完成、处理异常，直接显示图片或事件列表；不再重复呈现趋势图、识别率和批次筛选。所有上传记录的任务统一展示，旧的图片链接仍可打开对应证据。
3. 点击“上传图片”选择 JPEG、PNG 或 WebP 原图，无需填写批次名称；独立人工标签 CSV 在选填区域中选择。传输进度来自实际上传字节，服务器校验成功后直接进入待处理队列。可以勾选处理、处理全部，异常项可单独或勾选重试；已排队、运行中及成功完成的图片不会重复入队。
4. 待复核事件直接打开现有证据与人工结论界面，保存确认或排除后从待办移出，人工历史与原始输出分别保留。复核资格沿用单图识别到至少 6 名骑乘人员的既有规则，不由是否关联人员决定。
5. 点击“查看结果”或缩略图核对原图与检测框，右侧展示关联资料及各个车辆事件；可补充人员资料。资料按同一次导入的照片保存，弹窗显示实际适用图片数量。已完成列表支持按抓拍日期、关联状态和关键词检索，未完成任务不受历史日期条件影响。
6. 违章记录沿用图文表格、证据追溯与导出；首页传来的日期、地点、来源或时段条件在打开详情、关闭后保留，返回总览保留原日期范围。演示中缺失的抓拍时间与地点按图片标识稳定补齐，不写入原始数据库。

工作台流体进度沿用 `src/Capsule.tsx` 与 `src/vendor/luoban25-fluid-progress/`，来源为 luoban25.github.io 的 Fluid Progress。该来源仓库没有附带开源协议文件，对外发布前需取得作者许可或换掉。浏览器不支持 WebGL 时显示静态进度。

在 `frontend/` 运行 `npm run test:overview` 和 `npm run test:work` 检查统计、队列和处理请求范围，运行 `npm run build` 完成类型检查与构建。

## 联调记录

- 在独立临时数据库中，以 Chrome 操作真实后端与 Co-DETR v1 epoch 2。先选一张运行，再处理余图，两张均完成推理。测试图及测试复核保存在临时目录，发布包只含前端资源。
- 对一张 4096 × 6336 的多面板图比对 14 个真实检测框的图层数量，抽查首框相对原图的坐标。验证指定框、纯原图、4 倍滚动、确认违章、按人工来源查回、重新复核排除、原图追溯，以及复核前后批次得分保持一致。
- 用 16 个传输测试文件进行限速上传，观察到多个中间百分比，上传完成后才跳转至批次。现场自备 100 张的耗时与吞吐仍需在部署服务器实测。
- 已检查首页、工作台、事件详情在 320、375、390、768、820、1024、1440 像素宽度下的横向边界，已查看桌面与手机首页截图、桌面工作台和追溯弹窗截图。
- design-taste-frontend 的营销落地页门禁在首轮报告 37 项未通过，集中于全屏首图、顶栏导航、分屏节奏、CTA、栅格与静态锚点规则。本前端保留业务侧栏、同屏指标和 hash 路由，以上浏览器检查覆盖实际跳转、交互与布局。

接口字段以 [接口约定](../docs/接口约定.md) 和 [后台说明](../backend/README.md) 为准。

工作台优先使用新的统计接口；已有后台尚未重启、该接口返回 404 时，前端通过原有只读接口汇总同口径数据。兼容读取限制并发，缓存已完成图片的统计摘要，在识别进度、人工结论或关联版本变化后更新，当前运行中的服务也可直接展示趋势。
