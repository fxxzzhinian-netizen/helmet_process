## 输出与车辆归属

沿用交付入口的 2048 × 1280 等比缩放、相机版式裁切、灰色信息条及原图坐标映射，CPU 为 FP32、batch 1、4 线程、查询分块 4096。其他尺寸按全图推理。前端显示与模型输入应使用同一像素方向；后台已将带旋转 EXIF 的输入转正后用于两端。接口保留置信度至少 0.25 的有效框。坐标为相对原图左上角的像素 xyxy，右下为边界。D 是驾驶人，P0、P1、P2 是训练类别中的乘客角色。人框覆盖整名骑乘人员。

4096 × 6336 上下二联图的上图是下图某个矩形的放大，靠近下图边缘时该矩形被截短后再拉伸。`model/crop.py` 用两图的 SIFT 特征拟合横竖系数独立的仿射变换，定位成功时在 `panels` 的 `top` 项附加 `crop_of` 和 `source_box`。须同时满足：内点至少 20 个且占匹配的 60%，错切项不超过 0.005，横竖系数在 0.35–0.70 之间，窗口越出下图不超过 16 像素。任一项不满足即不附加，后台按无截取关系处理。两个画面照常各识别一次，检测框不因定位结果改变。在 444 张夜间二联图上定位成功 436 张，把下图窗口放大后与上图逐像素比较，相关系数均不低于 0.90。定位在 CPU 上每张约 0.5 秒。可在项目根目录执行 `python -m unittest model.test_crop` 检查。

模型服务的输出到此为止：画面范围、截取关系和检测框。以下整图结论与车辆归属规则由后台 `backend/rules.py` 执行。

`prediction` 使用人员合并后的判断：存在明确未戴盔人员为 no_helmet；存在人员且所有人的戴盔判断均为已戴为 helmet；其余为 unknown。相反类别的冲突人员不计作明确未戴盔。车辆事件使用下列独立规则，`detection_ids` 可直接查到原图证据：

- 在同一面板内，人员框与车辆框交集占二者较小面积超过 30%，且仅匹配到一辆车，才关联该人员。单车上任一关联人员未戴即生成一条 violation；有驾驶人、其余检出者均戴盔时为 clear。多个可区分的车辆各产生一个事件。
- 归属冲突、缺司机且只检出戴盔乘客、同座位多框、人员框高度重合或缺框均可转 review。涉及多个候选车辆的一组证据用 scope=unresolved；没有足够依据定位来源车辆时，保留这些框供人工核实。
- `backend/consensus.py` 先在每个画面内归并同角色且所有框两两 IoU 至少 0.85 的重复人员候选，保留全部原始框 ID。再把带截取关系的上图框映射到下图坐标，按车对车、人对人、IoU 至少 0.5 一对一匹配，位置重合优先，不用戴盔类别决定人员身份。任一已归为同一人的候选出现已戴/未戴冲突，`decision=unknown`，不凭分数高低覆盖冲突。角色冲突单独标记。只在一图检出的目标照常保留。
- 每个画面使用自己的原始框坐标绘制，但同一人共享合并判断；前端默认显示合并结果，可切换查看原始输出。`analysis` 提供人员判断、逐画面显示框和待确认数量；上下图的目标合并另记录在 `merged_detections`。同车有其他明确未戴盔人员时保留其违章证据，否则有冲突的车辆进入 review。
- 历史结果在图片详情读取时生成当前 `analysis`，不重新跑模型，也不改写原始输出、历史得分及人工复核记录。新运行任务按当前规则保存图级结论和事件。可运行 `python -m unittest backend.test_consensus backend.test_rules backend.test_backend` 检查。
- 没有截取关系的交付版式中，跨面板自动合并只接受每格一辆、各格人员类别及结论完全一致、车辆框内 ORB 特征通过几何匹配的情形。其余拼图只提交一个原图复核项，panel_candidates 中保留逐面板候选。该规则是基于画面外观的启发式判断，缺少跨帧车牌或人工车辆 ID。
