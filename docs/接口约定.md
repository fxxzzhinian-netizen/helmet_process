# v0.1 接口约定
统一同源 /api，JSON。ID 均为字符串。前端由后台同源托管构建输出，开发可代理。列表响应为数组。

- GET /api/batches；POST /api/batches（multipart：name、files 多文件、labels 可选 CSV，以 filename,prediction 标记 helmet/no_helmet）；GET /api/batches/{id} 返回 {id,name,status,total,processed,images:[{id,filename,status,prediction,truth}],score}。score 为 null 或 {correct,total}，仅完成样本计入当前成绩。列表不要求 images。
- POST /api/batches/{id}/run，JSON {image_ids:[...]}，省略或空数组为全部；异步执行。图片状态 pending/running/done/error。批次状态 pending/running/done/error，部分运行后可继续。
- GET /api/images/{id} 返回 {id,batch_id,filename,status,prediction,truth,width,height,error,detections,vehicles}；GET /api/images/{id}/original 提供原图。照片与框须同坐标空间。
- GET /api/reviews、GET /api/violations 均返回车辆事件列表，至少 {id,image_id,batch_id,filename,status,reason}，status 为 review/violation/clear，附 source（model/human）。POST /api/reviews/{id} 接受 {decision:"violation"或"clear",note:"..."}。
- 模型边界是独立的模型服务，见下方「模型服务」。模型对每张图片只返回 JSON {width,height,panels,detections}：panels 为 [{id,box}]，即切分出的各个画面；detections 为 [{id,box:[x1,y1,x2,y2],label,confidence,panel}]，label 使用训练类名。后台的判定规则 backend/rules.py 据此得出 prediction（helmet/no_helmet/unknown）和 vehicles [{id,detection_ids:[...],status,reason,scope}]，与模型输出一并保存为 model_result。仅有整图结论时不能捏造车辆归属。初始化或执行失败报错，后台呈现失败。模型版本标为 Co-DETR v1 epoch 2。
- 4096×6336 上下二联图的上图是下图某个矩形的放大。模型定位成功时，在 panels 的 top 项附加 `crop_of:"bottom"` 和 `source_box:[x1,y1,x2,y2]`（原图像素）；定位失败或其他版式不附加。后台先归并同画面、同角色且两两 IoU 至少 0.85 的重复人员候选，再将上图映射到下图，按几何重合度一对一配对（IoU 至少 0.5），不按戴盔类别优先匹配。相反类别冲突一律待确认，不取分数较高者覆盖。`merged_detections` 的 box 为下图坐标，包含 `role,decision,role_uncertain,detection_ids,agreement,reason`；agreement 为 agree、conflict、role_conflict、top_only、bottom_only。原始 detections 不变。
- 图片详情新增 `analysis:{version,prediction,cross_view_merged,raw_count,person_count,vehicle_count,uncertain_count,subjects,detections}`。subjects 是去重后的目标；analysis.detections 是逐画面的显示框，额外包含 subject_id，各画面沿用自己的原图坐标、共享同一人员的 decision（helmet/no_helmet/unknown），detection_ids 关联该人员全部原始证据。该只读投影也适用于旧结果，不改写旧 model_result、历史 score 或人工复核。前端默认绘制 analysis.detections，保留原始输出切换入口。
- 人工复核的唯一触发条件是单张图片去重、合并后的骑乘人员数量 `analysis.person_count >= 6`，包含恰好 6 人；新识别图片整图生成一条 `status=review`、`scope=image` 的事件。车辆不计入人数，驾驶人及乘客均计入，同人多框或上下图重复不重复计数。人员关联、角色/戴盔冲突、多车归属不明、空检测均不单独触发人工复核。人数不足 6 人时按可确认的未戴盔证据自动判定，无可确认的未戴盔证据则排除；原始不确定性仍在检测分析中保留。事件返回 `person_count`、`review_eligible`，后者仅由人数决定，复核保存接口同步强制校验。旧事件列表、详情和统计按当前规则展示，不改写原始模型证据、独立人工标签或已有人工结论。
- 可做兼容性字段补充。跨模块的行为变更在主聊天协调。

## v0.1.0 实现补充

- 标签 CSV 的表头只能是 `filename,prediction` 两列，含其他列时整个批次返回 400。原始上传字节地址为 `GET /api/images/{id}/uploaded`，坐标对应的显示图地址为 `GET /api/images/{id}/original`。两者在需要 EXIF 旋转时会不同。
- 批次级 `processed = done + failed`。入队后的图片在开始推理前处于 pending，`queued` 标记是否在队列中。识别请求返回 HTTP 202 和本次受理数量 `accepted`。
- 图片详情的 `model_result` 包含原始适配器输出和模型校验信息。`events` 是当前的业务事件，可能已由人工改判。事件的 `GET /api/events/{id}` 提供原判、结论来源、当前状态与人工历史。
- 复核请求可携带 `revision` 防止旧页面覆盖新结果。复核队列与违章记录均可使用 `batch_id`、`image_id`、`source` 过滤。完整字段及 CSV 限制见[后台说明](../backend/README.md)。
- `GET /api/analytics?days=7&batch_id=<id>`：识别工作台汇总。`days` 支持 7、14、30，省略批次表示全部批次；返回 `summary`、每日 `days`、`generated_at`。日期按北京时间，上传量按批次创建日，识别完成与失败按处理完成日；无历史失败时间的旧记录按批次创建日归组。事件及人员关联按识别日期汇总当前状态，人工改判和更换资料会更新对应日期的数据。骑乘人次是单图去重人数之和；失败率、图像识别率、人员关联率分别以已处理图片、有标签的已完成图片、已识别目标为分母，无样本时返回 null。接口只返回统计数据，不返回具体照片或人员详情。

## 模型服务

模型与网站分为两个进程。模型服务只接收图片字节并返回画面范围和检测框，不做戴盔结论和违章判定，不保存图片和记录，一次处理一张。在项目根目录执行 `python -m model.server --host 127.0.0.1 --port 8766` 启动。

- `GET /health` 返回 `{status,error,model_version,device}`，status 为 loading、ready 或 error。
- 后台的 `GET /api/model` 转发上述状态供页面展示，字段相同；连不上模型服务时 status 为 offline，3 秒内返回。
- `POST /predict` 的请求体是一张图片的原始字节，须带 Content-Length，上限 512 MiB。成功返回 200 和上文的模型结果。推理失败返回 500，模型加载失败返回 503，令牌错误返回 401，响应体均为 `{error}`。
- 后台通过 `HELMET_MODEL_URL` 调用，默认 `http://127.0.0.1:8766`。单次请求超时由 `HELMET_MODEL_TIMEOUT` 设置，默认 900 秒，首次请求包含模型加载。失败的图片标记为识别失败，模型服务恢复后可在工作台重试。
- 两端设置相同的 `HELMET_MODEL_TOKEN` 后，请求须带 `Authorization: Bearer <令牌>`。模型服务监听非本机地址时应设置令牌。
- 更换算法时保持上述请求和返回格式。类别名称或检测对象变化时，同步调整后台的判定规则 backend/rules.py。模型服务只输出置信度至少 0.25 的检测框。
