# 批次人员与违章关联

## 通用人员资料

“上传图片”弹窗里的“关联人员信息”保存一份对全部图片生效的人员资料：已识别的、之后才识别的、之后才上传的图片都按它关联，不需要每次上传图片时再传一遍。
可以和图片一起提交，也可以不选图片只保存资料。重新上传即替换，旧版本保留在数据库中；重复保存同一文件不新增版本。
某次导入通过“关联资料”单独传过资料时，那一次导入继续用自己的资料，不受通用资料影响。
文件格式、字段和配对方式与下文相同，弹窗内固定使用演示配对。

## 按批次关联

在任一批次详情或识别工作台点击“关联违章”，选择或拖入人员资料，直接保存关联。
上传弹窗仅保留文件上传入口与保存操作；统计、目标资料在批次详情和违章记录中查看。
资料按批次保存，允许先上传资料再运行识别；已经生成的目标也可后补、更换资料。

识别工作台与批次详情的图片区下方提供“违章关联”台账，按图片中的目标逐条显示人员、车辆、状态和现场照片。
每完成一张图片识别，台账自动更新；后补或更换人员资料后，已有目标的关联信息也自动更新。
仅已完成识别并生成事件的目标进入台账，待识别图片仍保留在图片队列中。导入预览中的配对数量与台账数量可能不同。
台账支持姓名、车牌、芯片和文件名搜索，以及关联状态、判定状态筛选。记录按识别完成时间倒序，每页 20 条。
右上角“导出 CSV”打开条件筛选弹窗，在当前列表范围内按关键词、姓名、人员编号、车牌、芯片、地址、批次、判定来源、记录状态和关联状态组合筛选；可选择按抓拍、识别或判定时间筛选日期范围，包含开始和结束当天。条件同时满足才计入，多个关键词用空格分隔。弹窗显示命中数量，导出包含其他页的全部匹配记录。
CSV 使用 UTF-8 BOM 编码，Excel 可打开。仅导出关联原始资料中的字段，表头统一使用中文，保留原始字段顺序与单元格值；同名中文表头增加数字后缀区分。按本次筛选结果逐列检查，只要至少一条资料有值就保留，整列为空则移除，数值 0 和 false 视为有效值。不增加序号、模型判定等生成字段；固定排除“关联方式”“演示资料”“关联目标”“身份关系”“辖区”“部门”“手机号”，包括对应的中英文原始字段别名，即使有值也不导出。
弹窗显示匹配记录数，导出按钮显示实际导出条数。未关联到原始资料的记录不生成空白行；旧版本仅保存了规范化资料时，重新上传相同文件即可补齐原始字段，保持原关联版本及判定不变。
原始 `manifest.csv` 的 2000 条、43 列逐列清点见[原始 CSV 字段清点](原始CSV字段清点.md)。
违章记录与待人工复核列表采用相同的图文表格，并各自支持筛选结果导出。点击缩略图或详情可查看原图与事件。

## 支持的数据

- CSV：兼容园区 `manifest.csv`，提供可下载的 UTF-8 BOM 模板，也支持 GB18030。
- JSONL：兼容 `records.jsonl` 的 `{file, record: {...}}` 嵌套结构。
- JSON：记录数组，或 `{records: [...]}`。
- 单个文件最多 20 MB、20000 条；人员编号、车牌和抓拍编号保留前导零。

| 含义 | 模板字段 | 园区字段 |
| --- | --- | --- |
| 照片文件名 | filename | file，取路径末尾文件名 |
| 人员编号 | person_id | memberNo，缺失时使用 mbId |
| 姓名 | name | ownerName |
| 身份关系 | relationship | ownerName 对应登记车主 |
| 车牌号 | plate_number | plateNumber，缺失时使用 carNo |
| 芯片编号 | rfid_chip | rfidChip |
| 抓拍时间 | captured_at | alarmTime，缺失时使用 createTime |
| 园区抓拍编号 | capture_id | id |
| 画面目标车辆 | target_vehicle_id | 模型生成的车辆标识；不能用 vehicleRecordId 代替 |
| 园区车辆记录 | source_vehicle_id | vehicleRecordId |
| 抓拍地点 | address | address |
| 辖区 | jurisdiction | areaName，regionName |
| 部门 | department | departmentName |
| 手机号 | phone | mobile，phoneNumber，ownerPhone，ownerMobile |

当前提供的数据有 2000 条资料，1998 条有姓名、2 条缺少姓名。
CSV 与 JSONL 的资料一致。原数据中的人工审核状态、违章类型与模型评分标签分别保留，不用于覆盖模型判断。

## 配对方式

**演示配对**：先按照片文件名匹配，没有对应资料时，按照片与目标序号做稳定的演示配对。
刷新、服务重启、重复上传不会随机换人。关联人员姓名下方保留人员编号，隐藏“演示关联人员”说明；详情资料也不展示该说明。配对方式本身不变，不代表真实人脸识别或实际骑乘人身份。
资料没有姓名时显示“未识别”，已有车牌、芯片和抓拍来源继续展示。

**按文件名匹配**：仅关联同名照片资料。多车同框时，需要 target_vehicle_id 证明目标归属；否则显示“未识别”。
同一照片或同一目标对应不同资料时显示“资料冲突”，不会静默任选一条。
完全重复的同一条记录不造成冲突。登记车主不会自动变成已经核实的驾驶人或乘客。

## 保存与追溯

预览接口不写入数据库。上传弹窗保存时自动校验资料，并使用当前关联版本检测并发修改；同一批次重复保存相同文件与方式不新增版本。
更换文件或配对方式后保留之前版本、来源文件、完整规范化资料、时间和当次匹配统计。
违章记录、待人工复核及事件详情都会返回身份信息；原始模型输出、评分和人工复核历史保持独立。
违章列表可以按姓名、人员编号、车牌、芯片搜索，并筛选已关联、未识别和演示配对。

人工复核的唯一触发条件是单张图片去重、合并后识别到至少 6 名骑乘人员，包含恰好 6 人；是否关联人员不影响资格。人数不足 6 人时，人员未识别、资料冲突、戴盔/角色冲突、多车归属不明或空检测都不触发人工复核。接口返回单图 `person_count` 与仅由人数决定的 `review_eligible`，列表、趋势统计、详情操作及复核保存接口采用同一规则。旧记录按当前规则展示，原始检测证据与已保存人工结论不改写。侧栏不显示数字角标。

## 接口

- `GET /api/association-template.csv`：下载资料模板。
- `GET /api/associations`：通用人员资料的当前版本 `revision` 与文件信息 `imported`，未上传时为 0 和 null。
- `POST /api/associations`：multipart，`file` 文件和 `mode=demo|filename`，保存为通用人员资料的新版本。
- `GET /api/batches/<batch_id>/associations`：当前关联、匹配统计、前 50 个目标预览、完整已识别事件 `rows`、版本历史。台账每 2 秒同步，并在批次识别进度或资料版本改变时立即刷新。
- `POST /api/batches/<batch_id>/associations/preview`：multipart，`file` 文件和 `mode=demo|filename`，只预览。
- `POST /api/batches/<batch_id>/associations`：同上，额外提供预览返回的 `revision`，保存新版本。
- 批次接口新增 `association` 文件版本信息，事件接口新增 `identity` 资料对象。
- 事件的 `recognized_at` 是识别完成时间，与 `identity.captured_at` 抓拍时间分开返回和导出；未提供抓拍时间时，表格标注“识别”。
