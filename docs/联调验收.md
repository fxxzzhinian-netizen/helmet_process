# v0.1.0 联调验收

2026-11-14 在 Apple M5、macOS arm64、Python 3.11 和本机 Chrome 完成。浏览器访问同源的正式构建，后台使用 Waitress、SQLite 与交付的 Co-DETR v1 epoch 2，使用与用户启动入口相同的 Python 环境。测试库和日常演示库使用不同目录。

| 用户动作 | 实测结果 |
| --- | --- |
| 在浏览器选择照片和人工标签 | 使用 3 张不同的项目原图，经页面创建批次并点击「运行整批识别」，全部完成真实前向。 |
| 检查模型分流 | 一条同车未戴盔事件自动进入违章记录。四联图因车辆跨面板归属不明确进入人工清单，另一张仅检测到车辆的照片也进入人工清单。 |
| 切换检测框 | 在 8192 × 6336 的原图上切换四种图层。原图无框，整车与骑乘人员能分开显示。逐一比较全部 50 个屏幕框与后台原图坐标，四边的归一化误差均小于对应边长的 0.1%。 |
| 人工复核、查回原图 | 在待审页按批次、事件编号定位，选择「确认违章」，保存说明。在违章记录搜索同一事件打开「追溯」，原图 ID 一致，来源为人工，留存一条变更历史，复核前后批次图级成绩一致。 |
| 重启后查回 | 重启独立测试服务，原批次、原图、检测框以及人工事件仍可查询。 |
| 批量上传 | 后台聊天通过 HTTP 一次接收 100 张真实 JPEG（156,457,688 字节），含四联大图。百张测试覆盖上传和原图读回，现场百张推理耗时及正确率待用户的评测集和目标服务器实测。 |

在项目根目录复跑模块检查：

```sh
.venv/bin/python -m unittest backend.test_backend backend.test_rules model.test_server model.test_crop -v
npm --prefix frontend run build
```

后台测试用可控适配器覆盖并发、重试、恢复与计分。上表中的浏览器识别流程使用真实权重。模型接入说明另列固定集归档评分、样本框核对与车辆归属限制。验收未向原非机动车管理平台写入业务记录。
